# QA1 — автоматизоване тестування Web API

Колекція: `postman/FilmHub-QA1.postman_collection.json`, формат Postman Collection v2.1.
28 послідовних запитів перевіряють C5 та B1 через HTTP без змін бізнес-логіки.

## Підготовка

Потрібен запущений FilmHub з доступною поточною базою та хоча б одним наявним жанром.
Ця інструкція не потребує міграцій, seed, ручних SQL-команд або змін `.env`/Compose.
Для локального запуску з уже налаштованим підключенням:

```powershell
dotnet run --project FilmHub.csproj --launch-profile http
```

`baseUrl` за замовчуванням — `http://localhost:5103`; для вже запущеного Docker-застосунку — `http://localhost:8081`.
Без завершального `/`. Змінні належать колекції, середовище Postman не потрібне.
`genreId` можна залишити порожнім: перший GET вибере жанр із наявних фільмів.
Якщо фільмів немає, задайте ID наявного жанру в `genreId` (його видно на `/Genres`).
Жанри колекція не створює та не видаляє. За відсутності жанру запуск завершується помилкою підготовки.

## Один запуск у Postman

1. **Import → Files** → вибрати `postman/FilmHub-QA1.postman_collection.json`.
2. Відкрити **Variables**, встановити `baseUrl`, за потреби `genreId`, зберегти.
3. Вибрати колекцію → **Run collection**. Залишити всі 28 запитів у початковому порядку, Iterations = 1, без data file.
4. Увімкнути **Keep variable values / Persist variables**, якщо ця опція є у вашій версії: це збереже маркер для наступного запуску.
5. **Run** запускає весь сценарій. У результатах перевірити assertions та відсутність script/request errors.

Запускайте колекцію цілком: окремий Send не виконує послідовність Runner.
Не редагуйте службові `ownerMarker`, `movieId`, `createBody`, `updateBody`, `followPath`.

## Що перевіряється

| Перевірка | Очікування |
| --- | --- |
| GET усіх | 200, JSON-масив DTO, унікальні ID за зростанням |
| POST | 201, Location, поля створеного фільму та наявний жанр; ID зберігається автоматично |
| GET за ID | 200, точні поля та ID створеного фільму |
| PUT → GET | 204 без тіла; потім нова назва, рік, null posterUrl, збережений жанр |
| DELETE → GET | 204 без тіла → 404 |
| B1 | envelope items/totalCount/skip/limit/nextLink, кількість, порядок, типи, значення за замовчуванням |
| nextLink | відносний шлях, наступний skip, незмінний limit, перехід за повернутим посиланням |
| Кінець сторінок | великий skip: порожній items, nextLink = null |
| 16 некоректних параметрів | 400 application/problem+json, status, errors потрібного поля |

Некоректні параметри: від’ємні числа, 0/101 для limit, текст, дроби, переповнення Int32, порожні/пробільні та повторені значення.
DTO перевіряються за ключами, типами, діапазоном року, вкладеними жанрами; POST/GET/PUT порівнюються з точними очікуваними даними.
Якщо після POST є лише один фільм, nextLink закономірно null: наступний запит перевіряє порожню другу сторінку.
Для демонстрації переходу за ненульовим nextLink потрібен хоча б один наявний фільм до запуску.
Під час перевірок пагінації уникайте паралельних записів: offset-пагінація не є snapshot.

## Безпека та повторний запуск

Кожен запуск генерує GUID-маркер `FilmHub-QA1:<guid>` у description та відповідну унікальну назву.
PUT/DELETE спочатку читають запис за збереженим ID та звіряють маркер і назву. При невідповідності запит пропускається з помилкою.
Початковий GET знаходить залишки лише за **точним збереженим маркером попереднього запуску та назвою**, повторно читає кожен запис і видаляє його через API.
Пошуку/видалення за загальним префіксом немає. Наявні чужі фільми використовуються тільки для читання.
Жанри, файли постерів та інші етапи не змінюються.

Після звичайного завершення тестовий фільм видалений. При втраті стану, аварійному завершенні процесу до експорту або ручному редагуванні маркера автоматичне очищення не гарантоване.
Без точного маркера колекція не намагається вгадувати власника залишків. Не запускайте паралельно одну копію зі спільним станом.
Перевірка власника і DELETE — окремі HTTP-запити; не редагуйте тестовий запис паралельно.

## Newman CLI

Після встановлення Node.js LTS один раз установіть Newman:

```powershell
npm install --global newman@6
```

З кореня репозиторію всі перевірки одним запуском:

```powershell
./postman/run-qa1.ps1 -BaseUrl http://localhost:5103
# За потреби: ./postman/run-qa1.ps1 -BaseUrl http://localhost:8081 -GenreId 1
```

Скрипт експортує поточні змінні в ігнорований Git файл `postman/.qa1-state.json` і використовує його наступного разу для очищення.
Код завершення Newman передається далі: 0 — успіх, ненульовий — помилка. Не використовується bail: помилка assertion не перешкоджає фінальному DELETE.
Переривання процесу може не дати Newman експортувати стан. Стан прив’язаний до конкретного API: використовуйте окремі копії папки для різних серверів.
Після зміни самої колекції старий state містить попередню версію: завершіть очищення на старій версії, потім приберіть state.

Прямий запуск без збереження стану (звичайне завершення все одно видаляє тестовий фільм):

```powershell
newman run postman/FilmHub-QA1.postman_collection.json --collection-var baseUrl=http://localhost:5103
```

Потрібна актуальна версія Postman/Newman з `pm.execution.skipRequest()`.

## Короткий відеозахист

1. Показати файл колекції та Variables з baseUrl; пояснити унікальний маркер і захист чужих записів.
2. Запустити всі запити через Collection Runner одним натисканням.
3. Показати POST 201, автоматичний movieId, GET 200; PUT 204 і оновлені поля наступного GET.
4. Показати B1 envelope, перехід за nextLink, термінальну порожню сторінку та 400 для некоректних параметрів.
5. Показати DELETE 204, фінальний GET 404 і підсумок assertions без помилок.
6. Повторити запуск: новий GUID, попередніх тестових фільмів після нормального завершення немає.

## Перевірка реалізації

JSON прочитано парсером; усі 33 скрипти скомпільовано V8 для перевірки синтаксису.
Повний HTTP-прогін саме колекції тут не виконано: Node.js/Newman відсутні в середовищі.
Це окремо від наявних інтеграційних тестів API, які запускаються через `dotnet test tests/FilmHub.Api.Tests/FilmHub.Api.Tests.csproj --no-restore`.
Перевірено 2026-10-27: 114 інтеграційних тестів пройшли, 0 помилок, 0 пропущених.
Перший запуск у sandbox не мав доступу до Windows Event Log; повторний запуск поза sandbox успішний.
JSON і синтаксис PowerShell-скрипта перевірено, `git diff --check` без зауважень.
